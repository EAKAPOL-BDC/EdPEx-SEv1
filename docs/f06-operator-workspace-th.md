# หน้าจอเจ้าหน้าที่ F06: มอบหมาย คำนวณ และตรวจผลรวม

ต่อจากบริการรับคำตอบ F06 เพิ่มหน้าจอผ่าน **พื้นที่ทำงาน → งานเก็บข้อมูล F06**
ใช้บริการ สิทธิ์ และ snapshot เดิม ไม่มี migration หรือการมอบสิทธิ์ใหม่ใน increment นี้
ไม่ได้เปลี่ยนข้อมูลหรือสถานะคลังบน Supabase ของผู้ใช้

## ก่อนเริ่มใช้

การมี F01–F06 ฉบับร่างในคลังยังไม่ทำให้เกิดรอบเก็บข้อมูล
ต้องตรวจรับ/เผยแพร่รุ่นแบบและรุ่นคำแปล เตรียมปฏิทิน/รอบ/บริบท ตรึงประชากร
และติดตั้ง migrations จาก increment ก่อนหน้าผ่านขั้นตอน development ที่กำหนด
การสร้างรอบ/ประชากร/เผยแพร่คลังยังไม่ได้เพิ่มเป็นหน้าจอในงานนี้

ผู้ปฏิบัติการที่ได้รับอนุญาตต้องเตรียม grant แต่ละขอบเขตก่อนใช้งาน
bootstrap เดิมไม่ได้มอบสิทธิ์ชุดใหม่โดยอัตโนมัติ และผู้ดูแลไม่สามารถมอบสิทธิ์ที่ตนไม่มี
การมอบหมาย F06 ไม่ได้ให้สิทธิ์กรอกแทนผู้ดูแล

| งานบนเว็บ | สิทธิ์ที่ตรวจจากฐานข้อมูลในขอบเขตนั้น |
|---|---|
| รายการรอบ/บริบท | อย่างน้อยหนึ่งใน selfassessment.assign, round.manage, calculation.run, result.submit, result.review |
| อ่านรายชื่อประชากรและมอบหมาย | selfassessment.assign **และ** population.manage |
| เปิด/ปิดทั้งรอบ | round.manage |
| เตรียมและยืนยันคำนวณ | calculation.run |
| ส่งชุดผลเข้าตรวจ | result.submit และ calculation.validate |
| อ่านสูตร/ผลรวมที่เปิดได้ | result.review และ calculation.validate |
| รับรอง/ส่งกลับ | result.review, result.approve, calculation.validate และเป็นคนละบัญชีกับผู้คำนวณและผู้ส่งตรวจ |
| ผู้รับมอบหมายเปิด/กรอกงานของตน | self.read / self.write ผ่านหน้าแบบประเมินตนเองเดิม |

## ขั้นตอนบนเว็บ

1. เลือกขอบเขต → **งานเก็บข้อมูล F06** → เลือกรอบและบริบท
   หน้าว่างอธิบายสิ่งที่ต้องเตรียม ไม่สร้างข้อมูลตัวอย่างหรือรอบจริงให้เอง
2. ขณะรอบเป็น `ready` เปิด **รายชื่อสำหรับมอบหมาย**
   อ่านเฉพาะ ST1/ST2 ในประชากรที่รอบตรึงไว้ แสดงสถานะมอบหมายโดยไม่ดึงคำตอบ
3. ตรวจรหัสประชากรให้ตรงกับบัญชีเจ้าของ ระบุหน้าที่จริง และเลือกระดับที่คาดหวัง 1–5
   **ทุกข้อคะแนนต้องเลือกเอง** รวม M/T ที่ไม่อยู่ในหน้าที่ ไม่มีค่าคาดหวังสมมติ
   เลือกด้าน M/T ที่เกี่ยวข้อง ข้ออื่นในกลุ่มคงอยู่ทุกข้อ
   คำถามใช้รุ่นคำแปลที่รอบตรึงไว้ บันทึกครั้งเดียวและแก้ย้อนหลังไม่ได้
4. เมื่อพร้อม เปิดรับคำตอบพร้อมเหตุผล ปุ่มแจ้งว่ามีผลกับ **ทุกแบบและทุกบริบทในรอบ**
   บริการเดิมตรวจช่วงเวลา รุ่นเผยแพร่ และประชากรอีกครั้ง
   ผู้ตอบเปิดงานผ่าน **แบบประเมินตนเองของฉัน**
5. ปิดรับคำตอบทั้งรอบพร้อมเหตุผล แล้วเปิด **เตรียมคำนวณ** ของ F06 บริบทที่ต้องการ
6. เลือก cutoff โดยหน้าจอแสดงและตีความเวลาในเขตเวลา IANA ขององค์กร
   กด **ตรวจผลก่อนบันทึก** เพื่อคำนวณตรวจแบบ dry-run ไม่มี run/source/results/audit ใหม่
   หน้าตรวจแสดงแบบ รุ่น บริบท cutoff และจำนวน series; ไม่เปิดคำตอบหรือคะแนนรายคน
7. กด **ยืนยันบันทึกชุดผล** ภายใน 30 นาที
   คำยืนยันลงลายมือชื่อด้วย Django signing ผูกบัญชี ขอบเขต บริบท cutoff request key และ input hash
   บริการอ่าน source ใหม่ภายใต้ transaction และล็อกรอบ ถ้า hash เปลี่ยน rollback ทั้งชุด
   key/คำยืนยันเดิม retry ได้โดยไม่สร้างผลซ้ำ ข้อมูลใหม่ต้องตรวจ dry-run ใหม่
8. ผู้มีสิทธิ์ส่งชุดผลเข้าตรวจพร้อมเหตุผล ผู้ตรวจเปิดหน้าชุดผลเพื่อ replay และตรวจ coverage
   บันทึก **รับรองผลรวม** หรือ **ส่งกลับให้จัดทำชุดผลใหม่** พร้อมเหตุผล
   แบบฟอร์มผูกกับ review token ของ sealed run ที่อ่าน และบริการตรวจการแยกคนอีกครั้ง
9. ประวัติแสดงชุดที่คำนวณ ส่งตรวจ รับรอง ส่งกลับ และชุดเก่าที่มี approval ใหม่แทน
   ชุด correction ที่รับรองอ้างกลับชุดรับรองก่อนหน้า ผล/การตัดสินเก่าไม่ถูกแก้

## ขอบเขตข้อมูลในหน้าเจ้าหน้าที่

- ผู้วิเคราะห์เห็น metadata และ receipt ไม่ได้รับ packet สูตร/ผลรวมถ้าไม่มีสิทธิ์ตรวจ
- เหตุผลการตรวจและการตัดสินเปิดให้บทบาทส่งตรวจ/ตรวจที่มี calculation.validate เท่านั้น
- ผลรวมอ่านจาก `review_summary()` เพียงช่องทางเดียว ไม่มีการ render raw snapshots/answers
- valid_n < 5 ซ่อน value, numerator, denominator และ quality counts
- บริบทที่มีหลาย generation ซ่อนค่าทุกรุ่นตาม policy ป้องกันการหักลบระหว่างรุ่น
- HTML ของแถวที่ซ่อนไม่แสดงค่าในตาราง ช่อง hidden หรือ data attributes
- ผลที่เปิดได้แสดงทศนิยมสองตำแหน่ง ใช้ ROUND_HALF_UP เพื่อแสดงผลเท่านั้น ไม่แก้ค่าที่เก็บ
- ไม่มีตัวกรองประชากรตามอำเภอใจหรือ export เพิ่ม; ประวัติ/รายชื่อมี pagination
- ทุกหน้าใหม่ต้อง login และ no-store การเปลี่ยนสถานะใช้ POST + CSRF
- ตัวเลือก checkbox หลายข้อยังอยู่เมื่อสลับไทย/อังกฤษ โดยเก็บชั่วคราวในหน่วยความจำของหน้า
  เมื่อสลับภาษาบนหน้าตรวจ dry-run ต้องกดตรวจใหม่เพื่อสร้างคำยืนยันใหม่

F06 ยังเป็น self-report ไม่มีคะแนนผู้ประเมินหรือช่องหลักฐาน
การรับรองชุดผลนี้ไม่เปลี่ยนทั้ง CollectionRound เป็น approved และยังไม่เผยแพร่ผล

## การตรวจที่เพิ่ม

`tests.test_operator_web` มี 22 tests ใช้ Django Client ที่เปิด CSRF checks
ครอบคลุมการมอบหมายจริง การเปิด/ปิด สิทธิ์/ขอบเขต/เจ้าของ ระดับคาดหวังที่ไม่ได้เลือก
dry-run/commit/retry การปลอม/หมดอายุ/สลับบัญชีของคำยืนยัน การเพิกถอนสิทธิ์
rollback เมื่อ source เปลี่ยน เขตเวลา การส่งตรวจ/รับรอง/ส่งกลับและ correction
การซ่อนข้อมูลใน HTML ภาษาไทย/อังกฤษ และเมนู/ประวัติที่ไม่มีผลข้างเคียง

`node --test tests/portal_language.test.js` ตรวจสคริปต์สลับภาษาจริงผ่าน DOM boundary fixture
รวม checkbox ชื่อซ้ำ radio/select หลายค่า และไม่คืน CSRF token เก่า
เป็นการตรวจ handler ไม่ใช่การทดสอบใน browser จริง

ผล smoke ภายในใช้ SQLite เพื่อทดสอบฟอร์มและบริการเท่านั้น
CI PostgreSQL ใช้ migrations/SQL guards เดิมร่วมกับ tests ใหม่; ผลรันจริงระบุใน PR
ยังต้องทำ browser/UAT บนอุปกรณ์จริงและตรวจรับคำแปลก่อนใช้งานจริง

รับข้อมูล F01–F04 แบบแยกตัวตน, F05 ตรวจหลักฐาน, personal gap,
