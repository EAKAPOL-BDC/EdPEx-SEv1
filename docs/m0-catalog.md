# M0 catalog — เครื่องมือฐาน 1.1 / Blueprint 1.2

ไฟล์ต้นฉบับที่ผู้ใช้ส่งเก็บแบบคงทุกไบต์ใน `docs/source/EdPEx_System_Blueprint_v1.md`
และ `docs/source/EdPEx_6_Instruments.md` โดยรักษาไฟล์ที่หน้าแรกของ Repository ไว้ด้วย
เนื้อหาเมื่อปรับรูปแบบ newline ตรงกันทั้งสองตำแหน่ง ใช้ `docs/source/` เป็นโฟลเดอร์
ไม่ได้ใช้ branch ชื่อนี้เป็นแหล่งเอกสาร

## ใช้ทะเบียน

- `catalog/questions.json`: คำถาม 190 รายการ รวมข้อในตาราง ข้อเขียนในย่อหน้า ชุด K แยก F01/F02 และข้อย่อยที่ต้นฉบับกำหนดให้ขยาย
- `catalog/instruments.json`: หน่วยตอบ กลุ่ม และ workflow ของเครื่องมือทั้งหก
- `catalog/ancillary_fields.json`: ฟิลด์ประกอบที่ไม่มี question_id ในต้นฉบับ แยก namespace ภายในชัดเจน
- `catalog/indicators.json`: 63 รหัสหลัก พร้อมคำถาม สูตร กลุ่ม วิธีวัด และมิติแยกผล
- `catalog/formulas.json`: นิยามสูตร 20 ชนิด อ้างข้อ 11; ยังไม่ใช่ calculation engine ของ M2
- `catalog/groups.json` และ `catalog/scales.json`: กลุ่ม 17 รหัสและมาตรา ไม่เปิด C3.2/S2/SP-1 เพิ่มเอง
- `catalog/instrument_sections.json`: คำชี้แจง เกณฑ์ ตัวเลือก และข้อมูลประกอบต้นฉบับครบทุกส่วน รวมช่องที่ต้นฉบับไม่ได้ตั้ง question_id
- `catalog/requirements.json`: ข้อ 1–33 พร้อมข้อความต้นฉบับ ระยะงาน และไฟล์ที่เกี่ยวข้อง
- `catalog/translations.json` และ `catalog/glossary.json`: inventory ไทย–อังกฤษและศัพท์อังกฤษรอตรวจรับ
- `catalog/answer_keys.server.json`: เฉลยสำหรับ F01/F02 เท่านั้น ห้ามนำไฟล์นี้ไปเป็น respondent schema

ส่วนต้นฉบับและ translation inventory ที่มีคู่มือผู้ดูแล/เฉลยติด `audience=server_only`
การสร้างหน้าผู้ตอบในระยะถัดไปต้องเลือกเฉพาะรายการ respondent ที่ผ่านการรับรอง
ห้ามส่ง raw source sections หรือทั้งโฟลเดอร์ catalog ไปยัง browser โดยตรง

ดูตารางที่อ่านเปรียบเทียบได้ใน [mapping](m0-mapping.md) และ [traceability](requirements-traceability.md)
รหัสตัวเลือกใหม่เป็นกุญแจภายในที่คงที่ ข้อความไทยต้นฉบับอยู่ในทะเบียนพร้อมตำแหน่งบรรทัด
รหัสข้อย่อย `-CAUSE`, `-FIX`, `-EX` มาจากแม่แบบที่ต้นฉบับระบุ ไม่ใช่ตัวชี้วัดเพิ่ม
ช่องประกอบที่ไม่มีรหัส เช่นชั่วโมงดูงานจริง และแผนพัฒนา F06 เก็บใน source sections;
ระยะสร้างฟอร์มต้องตั้ง field key ภายในแยกจาก baseline question_id

## ข้อคงที่

F06 ใช้ `assessment_method=self_report` และรุ่น 1.1 ไม่มี upload ผู้ให้คะแนนแทน หรือ reviewer step
ตัวอย่างและแผนพัฒนาเลือกกรอก ไม่มีผลต่อ 7.4-6 การตรวจหลักฐานยังใช้กับ F05
7.3-43 หารประชากรทั้งหมด ส่วน 7.4-3/4 หารผู้ตอบคะแนนครบตามชุด
K ของ F01/F02 ยังคงตรวจคำตอบถูกผิด โดย U ต่างจาก missing
F06 ต้องเลือก latest submitted revision ณ cutoff ใน M2/M4 ไม่ใช้คะแนนสูงสุด

ภาษาไทยเป็นค่าเริ่มต้น ใช้รหัสคำถาม/ตัวเลือก/สูตรร่วมทั้งสองภาษา
ไม่มีการอ้างว่าคำแปลอังกฤษผ่านการรับรอง: ค่าอังกฤษที่ยังไม่มีเป็น null และสถานะ missing
glossary เป็น draft `needs_review` ต้องแปลและตรวจความหมายครบก่อนเปิดรอบสองภาษาใน M3
ข้อ 33 ทั้งหมดอยู่ใน traceability รวมการไม่เสียคำตอบเมื่อสลับภาษา การตรึง bundle
วันที่/ฐานปี การแยก cache ตามภาษาและสิทธิ์ และ notification/export

## รันเฉพาะงาน offline

```text
python scripts/build_m0_catalog.py
python -m unittest discover -s tests -p "test_m0*.py" -v
```

ใช้ Python standard library เท่านั้น ไม่โหลด Django settings ไม่เชื่อม Supabase ไม่ seed และไม่ migrate
การสร้างซ้ำให้ผล JSON เดิมจากเอกสารเดิม การทดสอบนี้ตรวจทะเบียนและความเชื่อมโยง
ไม่ใช่ผลทดสอบ CAL/UAT/NEW/LANG ของระบบที่ยังไม่ได้สร้าง

## สิ่งที่ต้องรักษาสถานะตามจริง

PDF รายชื่อตัวชี้วัดดั้งเดิมไม่ได้แนบในงานนี้ จึงเก็บ `original_name=null`
พร้อมเหตุผล ไม่แต่งชื่อทางการขึ้นจากชื่อคำถาม รหัสทั้ง 63 และ binding มาจากเครื่องมือที่ส่งมา
ชื่อแสดงผลที่ได้จากคำถามเป็นข้อความเพื่อทบทวน ไม่ใช่ชื่อจาก PDF
ไม่สร้างประชากร เป้าหมาย คู่เทียบ หรือผลย้อนหลังสมมติ

ขอบเขตงานครั้งนี้คือต้นฉบับและทะเบียนตามคำสั่งผู้ใช้ล่าสุด
Prompt ที่ฝังใน Blueprint ข้อ 18/32 เป็นเนื้อหาอ้างอิง ไม่ได้อนุญาตให้รัน M1–M7 หรือเปลี่ยนฐานข้อมูล
ต้นแบบหน้าจอหกหน้าตามข้อ 29/31 และ runtime ของระบบยังเป็นงานต่อไป ไม่อ้างว่าจบ M0 ทุกเกณฑ์ของ Blueprint
