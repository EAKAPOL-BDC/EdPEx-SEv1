# แกนคำนวณ M2 — รุ่นพัฒนาสำหรับทดสอบ

> รายงานนี้อธิบายการส่งมอบแกนคำนวณครั้งแรก ส่วนรอบคำนวณและ source snapshots
> ที่เพิ่มภายหลังอยู่ใน [รอบคำนวณและการตรวจผลย้อนหลัง](m2-snapshots-th.md)

ฐานข้อกำหนด: System Blueprint 1.2 ข้อ 11–12 และ Instruments 1.1 ใน `docs/source/`

เพิ่มฟังก์ชันคำนวณจริงใน Python แล้ว แยกจาก Django และฐานข้อมูล รองรับ 20 formula keys
พร้อมตรวจการผูก 63 ตัวชี้วัดใน catalog เดิม แบบฟอร์ม F01–F06 รุ่น 1.1 ในฐานข้อมูลผู้ใช้
ยังเป็นฉบับร่าง ขั้นนี้ไม่ต้องนำเข้าซ้ำหรือรัน migration และยังไม่มีปุ่มคำนวณในหน้าเว็บ

## สิ่งที่ส่งมอบ

| ไฟล์ | หน้าที่ |

## ผลทดสอบ

รันบน Python 3.12 ในเครื่องพัฒนา โดยไม่เชื่อม Supabase:

```bash
python -m unittest tests.test_m0_catalog tests.test_m0_bindings tests.test_m0_source_semantics tests.test_m2_golden tests.test_m2_validation
```

ผล: **69 tests ผ่าน** แบ่งเป็น catalog/source เดิม 26, CAL-01–18 จำนวน 18,
และการตรวจกรณีขอบ/คุณสมบัติ 25 รายการ ชุดทดสอบเดิมของ Django ค้นพบไฟล์ใหม่ตามรูปแบบ
`test*.py` โดยอัตโนมัติ ผล local นี้ไม่ใช่หลักฐานว่า CI บน GitHub ผ่านแล้ว

ลองรันผ่าน `manage.py test` ใน scratch ด้วย แต่ยังรันไม่ได้เพราะ environment นี้ไม่มี Django
(`ModuleNotFoundError: No module named 'django'`) จึงใช้ผล unittest ด้านบนสำหรับ local
และใช้ workflow Test ที่ติดตั้ง dependencies และ PostgreSQL สำหรับการตรวจร่วมกับ Django

## สัญญาข้อมูลสำหรับเชื่อมต่อในขั้นถัดไป

- `AnswerRow.unit_id` คือหน่วยตอบที่ไม่ซ้ำในขอบเขตเดียว เช่น คนหรือองค์กรตามนิยาม C5.3
  ต้องใช้นิยามและ stable ID เดียวกันทุกกลุ่มที่จะนำมารวม ห้ามใช้หมายเลขแถวแทนหน่วยจริง
- `Answer` ใช้สถานะ `answered`, `missing`, `not_applicable`, `unable_to_assess`,
  `not_shown`, `skipped` แยกกัน คะแนนใช้ integer/Decimal และตัวเลือกใช้ stable code
  ไม่รับ float, boolean, NaN, Infinity, ตัวเลขนอกมาตรา หรือป้ายตัวเลือกที่แปลแล้ว
- คำตอบที่ไม่ปรากฏใน row ถือเป็น missing ต้องส่งสถานะ not_shown โดยชัดแจ้งเมื่อคำถามไม่ได้แสดง
  ค่าที่ไม่ได้เป็นคะแนนต้องไม่มี value และ SELF_DIMENSION ที่ NA ต้องมีเหตุผล
- F06 ใช้ self-report เท่านั้น ตัวอย่างพฤติกรรมไม่มีผลต่อคะแนน ไม่มีหลักฐานหรือผู้ประเมินมาเพิ่มคะแนน
  F05 ใช้ attendance ที่ตรวจรับและตรวจหลักฐานแล้วตามข้อกำหนดคนละชุด
- ค่าผลเก็บ numerator/denominator; `value` ใช้ Decimal precision 50;
  `display_value()` ปัดสองตำแหน่งด้วย ROUND_HALF_UP ค่าปัดไม่ย้อนเข้าเกณฑ์หรือการรวมผล
- `valid_answers`, `na`, `missing`, `unable_to_assess`, `not_shown`, `skipped`
  นับช่องคำตอบในชุดข้อที่เลือก ส่วน `valid_n`, `complete`, `submitted_partial`,
  `not_submitted`, `passed`, `below_threshold` นับหน่วยตอบ ไม่ใช่จำนวนข้อ
  ใน ADMIN_MEAN คนที่ตอบ 4/5 ยังเป็น valid_n แม้ยังไม่ complete 5/5
- หากประชากรของสูตรต่อประชากรยังไม่กำหนด คืน `insufficient_population_definition`
  พร้อม denominator=null; ถ้าตรึงประชากรที่มี 0 คน คืน `no_valid_data` พร้อม value=null
  สูตรดิจิทัลอาจได้ computed 0 เมื่อประชากรมีคนแต่ไม่มีผู้ผ่าน ซึ่งต่างจากการไม่มีนิยามตัวหาร
- attendance ต้องเป็นข้อมูลที่คัดเลือกรุ่นล่าสุดและกรองวันที่กิจกรรม/ช่วงการทำงานแล้ว
  ใช้บุคลากร+กิจกรรม+session เป็นหน่วยตรวจซ้ำ สำเนาที่ตรงกันนับครั้งเดียว
  สำเนาที่ขัดแย้งถูกปฏิเสธให้แก้ข้อมูลก่อนคำนวณ ต้องไม่ส่งทั้งยอดรวมกิจกรรมและ session ย่อยซ้ำกัน
- การเลือก revision ต้องมีเวลาพร้อม timezone; cutoff รวมจังหวะเวลาที่เท่ากัน
  เรียงจากเวลาส่งล่าสุด และเลข revision เมื่อเวลาส่งตรงกัน ร่างไม่ใช่แหล่งคำนวณ
  รหัส revision หรือเลขรุ่นที่ขัดแย้งถูกปฏิเสธ
- การรวมกลุ่มต้องมีนิยาม series ตรงกันทั้ง scope, period, period type, indicator,
  context, dimension, method, response unit และสูตร/รุ่น รวมได้เฉพาะหน่วยตอบที่ไม่ทับกัน
  ไม่ใช้วิธีนี้เฉลี่ยเปอร์เซ็นต์รายไตรมาสเป็นปีหรือรวมข้อมูลย้อนหลังที่ไม่ทราบตัวหาร
- input ที่ผิดรูปแบบยก `CalculationInputError`; service ต้องบันทึกเป็นข้อผิดพลาดที่ตรวจสอบได้
  ห้ามแทนด้วยผลศูนย์ โครงสร้างผลเป็นข้อมูลภายใน มีตัวตั้ง/ตัวหารและ unit IDs เพื่อป้องกันนับซ้ำ
  ต้องผ่านสิทธิ์และ suppression ก่อนสร้าง payload แสดงหรือส่งออก

## ขอบเขตที่ยังต้องทำก่อนตรวจรับ M2 ทั้งระยะ

1. โมเดล/migration แบบต่อยอดสำหรับ calculation run/result และ source manifest ที่บันทึกถาวร
   รวม cutoff, source revision IDs, population snapshot, question/formula hashes, engine commit
   และ replay ที่พิสูจน์ว่าผลเก่าไม่เปลี่ยนจากการแก้ข้อมูลต้นทาง
2. บริการและ API ตรวจสิทธิ์ราย scope พร้อม transaction/idempotency และเส้นทางรับรองผล
   การตรวจ context ในฟังก์ชันบริสุทธิ์ไม่ใช่ระบบ authorization
3. ตัวเชื่อมฐานข้อมูลเลือกรุ่นเครื่องมือ/คำตอบ/attendance ที่ถูกต้อง ตรวจ F04 appointment/context,
   ประชากรและวันทำงาน ตรวจ session ซ้อนกัน และ snapshot definitions ก่อนเรียก core
4. Historical raw/aggregate พร้อม provenance และข้อจำกัด การเปรียบเทียบ series และการรวมรายปี
   จากข้อมูลต้นทางแบบไม่นับคนหรือชั่วโมงซ้ำข้ามไตรมาส
5. Suppression และการเผยแพร่ผลตามสิทธิ์อยู่ในระยะ dashboard/release;
   engine นี้ยังไม่คืนข้อมูลผ่าน endpoint สาธารณะ

ไม่ได้เปลี่ยนสถานะนิยามสูตรใน catalog เดิมให้เป็น deployed เนื่องจากยังไม่เชื่อมบริการคำนวณจริง
ไม่ได้เปลี่ยนเอกสารต้นฉบับหรือเนื้อหาเครื่องมือ และไม่ได้ merge/deploy ระบบในงานขั้นนี้
