# NEXORA: ปรับหน้าระบบด้วยโลโก้และมาสคอต

รุ่น Brand Interface · 17 กันยายน 2569

## สิ่งที่ปรับ

- หน้า `/admin/`: หัวเว็บใช้โลโก้ NEXORA เดิม แถบต้อนรับพร้อมมาสคอต ปุ่มไปพื้นที่ทำงานและคู่มือ พื้นที่หลักขยายตามหน้าจอ พร้อมแยกเครื่องมือและการกระทำล่าสุดเป็นสองคอลัมน์บนจอกว้าง และคอลัมน์เดียวบนจอเล็ก
- หน้าเข้าสู่ Admin: จัดโลโก้ มาสคอต และแบบฟอร์มในแผงเดียว อ่านชื่อช่องและปุ่มได้ชัดเจน
- หน้าพื้นที่ทำงานและจัดการระบบขององค์กร: เพิ่มมาสคอตในส่วนต้อนรับ ขนาด 112 พิกเซลบนจอกว้าง และลดเหลือ 48–92 พิกเซลตามพื้นที่หน้าจอ
- หน้าเข้าสู่ระบบหลัก: ใช้มาสคอตเดิมขนาดพอดี บนมือถือยังเห็นภาพขนาดเล็กข้างข้อความต้อนรับ
- ส่วนหัวเว็บและหน้าสำรวจ: ใช้ส่วนแสดงโลโก้เดียวกัน รักษาอัตราส่วน ตัดเฉพาะพื้นที่โปร่งใสด้วย CSS ไม่แก้ไฟล์ต้นฉบับ
- ใช้พื้นขาว/ม่วงอ่อนและสีทองเป็นจุดเน้น มีเส้นแบ่งบาง ระยะห่างสม่ำเสมอ ลดกรอบและเงาหนัก หน้าฟอร์มไม่มีมาสคอตลอยทับคำถาม
- Admin ยังคงสลับธีมสว่าง/มืดได้ มีกรอบโฟกัสสำหรับคีย์บอร์ด และรักษาข้อความสองภาษาในส่วนที่เพิ่ม

โลโก้และมาสคอตเป็นไฟล์เดิมใน `apps/accounts/static/portal/branding/` ไม่มีการสร้างแบบใหม่หรือเปลี่ยนสี/รูปทรง ทั้งสองไฟล์โหลดจากระบบ ไม่มีบริการภาพหรือฟอนต์ภายนอกเพิ่ม

## ติดตั้งบน Windows

1. ดาวน์โหลด `nexora-brand-interface.zip` แล้วแตกลง `Downloads\nexora-brand-interface` ให้ไฟล์ `nexora_web_update.py` อยู่ในโฟลเดอร์นี้โดยตรง
2. หยุดเว็บเดิมด้วย **Ctrl+C** แล้วรันใน PowerShell เดิม:

```powershell
& "$env:USERPROFILE\EdPEx-Web\EdPEx-SEv1\.venv\Scripts\python.exe" "$env:USERPROFILE\Downloads\nexora-brand-interface\nexora_web_update.py" --apply-schema
```

3. เมื่อเห็น `Starting development server` เปิดหน้าที่ต้องการและกด **Ctrl+F5**:
   - พื้นที่ทำงานหลัก: `http://127.0.0.1:8000/workspace/`
   - เข้าสู่ระบบหลัก: `http://127.0.0.1:8000/login/`
   - หน้าดูแลระบบตามภาพที่ส่งมา: `http://127.0.0.1:8000/admin/`

เปิด PowerShell ค้างไว้ขณะใช้งาน ที่อยู่นี้ใช้กับเครื่องที่รันเว็บ ไม่ใช่เว็บไซต์ออนไลน์สาธารณะ ชุดนี้รวมศูนย์คู่มือและงานรุ่นก่อน ไม่มี migration ใหม่ การติดตั้งไม่เพิ่มสิทธิ์หรือเปลี่ยนบัญชี/รหัสผ่าน

## การใช้งานและสิทธิ์

หน้า Admin ใช้สิทธิ์ `is_staff` และสิทธิ์โมเดลตาม Django เดิม รายการผู้ใช้ กลุ่ม เพิ่ม แก้ไข และประวัติยังสร้างจากกลไกเดิม ปุ่มออกจากระบบยังเป็น POST พร้อม CSRF การคลิก “ไปพื้นที่ทำงาน” ไม่ทำให้ได้สิทธิ์ขององค์กรเพิ่ม ระบบตรวจขอบเขตองค์กรเดิมทุกครั้ง

พื้นที่ทำงานหลักเป็นทางเข้าการประเมิน คำนวณ และ Dashboard ของ NEXORA หน้า Admin เป็นหน้าดูแลบัญชีและสิทธิ์ทางเทคนิค

## การตรวจที่ทำแล้ว

- ชุดทดสอบเดิมผ่าน 10 กรณี: เข้าสู่/ออกจากระบบ, การป้องกันเข้าสู่ระบบ, CSRF, ขอบเขตสิทธิ์หลังบ้าน, ตำแหน่งเมนู และหน้าประเมิน
- เปิดอ่านและเรนเดอร์ผ่าน Django client 13 หน้า รวม Admin หลัก รายการแอป รายการผู้ใช้ เพิ่ม/แก้ไขผู้ใช้ popup หน้าเข้าสู่ระบบ หน้าหลัก และหน้าสำรวจ
- ตรวจภาษาไทย/อังกฤษ รายการโมเดลตามสิทธิ์ บัญชี staff ที่ไม่มีสิทธิ์ต้องเปิดรายการผู้ใช้ไม่ได้ และ POST ออกจากระบบที่ไม่มี CSRF ต้องถูกปฏิเสธ
- ตรวจไฟล์ภาพ/CSS/JavaScript ที่อ้างอิงว่าพบครบ และตรวจ syntax ของ CSS กับ template

ยังไม่ได้ตรวจภาพและการกดใช้งานบน Chrome/Windows ของผู้ใช้ เครื่องมือตรวจเว็บในรอบนี้เปิดเว็บทดสอบภายในไม่ได้ จึงต้องตรวจขนาดหน้าจอและการซูมจริงหลังติดตั้ง ไม่ถือว่าผ่านการรับรอง WCAG หรือการทดสอบกับผู้ใช้ทุกกลุ่มแล้ว

## จุดแก้ไขสำหรับนักพัฒนา

- โลโก้ร่วม: `apps/accounts/templates/portal/components/brand_logo.html`
- มาสคอตร่วม: `apps/accounts/templates/portal/components/brand_mascot.html`
- ขนาดและส่วนแบรนด์ร่วม: `apps/accounts/static/portal/brand.css`
- ธีม Admin: `apps/accounts/static/portal/admin-theme.css`
- Template Admin: `templates/admin/base_site.html`, `index.html`, `login.html`

ส่วน Admin ใช้ template inheritance เพื่อรักษาแบบฟอร์ม รายการตามสิทธิ์ และประวัติเดิม โหลด CSS เพิ่มหลัง Django responsive styles เพื่อไม่ให้ขนาดหน้าจอเขียนทับเลย์เอาต์ใหม่ การปรับครั้งต่อไปควรตรวจรายการแอปและ popup ด้วย ไม่ใช้แถบต้อนรับหน้าหลักซ้ำในทุกฟอร์ม
