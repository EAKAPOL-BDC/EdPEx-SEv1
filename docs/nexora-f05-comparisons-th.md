# F05 ข้อมูลจริงและ Dashboard เปรียบเทียบ

## สิ่งที่เพิ่ม
- เมนู “กิจกรรมบุคลากร F05”: สร้างรอบจาก F05/ชุดคำแปลที่เผยแพร่แล้ว
- ใช้ทะเบียนบุคลากร ST1/ST2 ที่ตรึงไว้ในรอบเดียวกัน
- บันทึกกิจกรรม/ครั้ง/บุคลากร วันเวลา ชั่วโมงอบรม ชั่วโมงดูงาน หมวด ผู้จัด สถานที่ เลขอ้างอิงหลักฐาน สิ่งที่เรียนรู้ การนำไปใช้ และผลติดตาม 30–90 วัน
- เก็บฉบับร่าง ส่งตรวจ ขอแก้ไข ตรวจรับ หรือไม่รับรายการ พร้อมประวัติผู้ดำเนินการ เวลา และเหตุผล
- ใช้การอ้างอิงหลักฐานที่จัดเก็บภายนอก ไม่ใช่ระบบอัปโหลดเอกสาร
- ตรวจชั่วโมงไม่เกินเวลาจริง ห้ามรับกิจกรรมที่ยังไม่จบ ต้องยืนยันหลักฐานก่อนตรวจรับ
- ชั่วโมงมากกว่า 12 หรือเวลาชนกับรายการที่ตรวจรับแล้ว ต้องมีคำชี้แจงจากผู้ตรวจ
- ป้องกันรายการซ้ำตามกิจกรรม/ครั้ง/บุคลากร ป้องกันการบันทึกจากหน้าที่ข้อมูลล้าสมัย
- ประวัติรายการและผลตรวจเป็น append-only พร้อม PostgreSQL triggers ป้องกันการแก้/ลบประวัติ
- ปิดรอบแล้วคำนวณเฉพาะรายการตรวจรับ ณ cutoff ผ่านสูตรเดิม และเก็บตัวตั้ง ตัวหาร ต้นทาง สูตร และ checksum
- เชื่อมการส่งตรวจผลรวม/รับรอง/ข้อยกเว้นผู้ดูแลเดิม และแสดงผลใน Dashboard/CSV เดิม
- กลุ่มเล็กและผลหลายรุ่นยังถูกซ่อนตามกติกา F05 ต้องมีอย่างน้อย 5 ผู้เข้าร่วมที่ตรวจรับและประชากร 5 หน่วย; ค่า passed ระหว่าง 1–4 ถูกซ่อนด้วย

## เปรียบเทียบผลจริง
หน้า “เปรียบเทียบผลจริง” จากหน้าสรุปผลรับรอง แยกจากชุดข้อมูลสาธิต
เทียบเฉพาะช่วงรายงาน รุ่นแบบฟอร์ม บริบท วันที่ cutoff ตัวชี้วัด มิติ วิธีวัด สูตร และหน่วยเดียวกัน
ระบุรอบต้นทางของทุกแถบ ไม่รวมประชากรหรือคะแนนอัตโนมัติ ไม่ดึงค่าที่ถูกซ่อนกลับมา
ชุดผลที่ตรวจความถูกต้องไม่ผ่านจะถูกเว้นและแจ้งจำนวนชุดที่ไม่ผ่าน
เลือกช่วงรายงานและค้นหาตัวชี้วัดได้

## วิธีใช้ F05
1. ตรวจและเผยแพร่แบบฟอร์ม F05/ชุดคำแปลในคลังตามขั้นตอนเดิม
2. เปิดเมนูกิจกรรมบุคลากร F05 → สร้างรอบ เลือกช่วงรายงานที่รับรองแล้ว
3. หน้าจัดเตรียมรอบ: กำหนดประชากร เพิ่มรายชื่อ ตรวจและตรึงรายชื่อ เตรียมพร้อม แล้วเปิดรอบ
4. เปิด F05 → บันทึกการเข้าร่วม → เลือกบุคลากรและกรอกข้อมูล ส่งตรวจ
5. ผู้มี source.manage และ calculation.validate เปิดรายการ ยืนยันหลักฐานและบันทึกผลตรวจ
6. กลับหน้ารอบ ปิดรอบ แล้วคำนวณชุดผลในหน้า F05
7. ส่งตรวจผลรวมและรับรองผ่านขั้นตอนเดิม ก่อนเปิด Dashboard
8. การแก้รายการที่เคยตรวจรับจะสร้าง revision ใหม่และต้องส่งตรวจอีกครั้ง ไม่แก้ชุดผลเก่า

## สิทธิ์
source.manage สำหรับบันทึกและดูข้อมูลบุคลากร; calculation.validate สำหรับตรวจหลักฐาน
calculation.run สำหรับคำนวณ; result.submit/result.review/result.approve สำหรับชุดผลตามบริการเดิม
ไม่ได้เพิ่มสิทธิ์ใหม่ให้ผู้ใช้หรือเปลี่ยนรหัสผ่าน

## Migration
calculations.0008_activity_sources เพิ่มตารางกิจกรรม/ประวัติ
calculations.0009_activity_guards เพิ่มการป้องกันประวัติและรองรับ F05 ใน stored source โดยคงกฎรับรองผลเดิม
ไม่มีการเขียนทับข้อมูลคำตอบเดิมหรือ reset ฐานข้อมูล

## ขอบเขตการตรวจ
ทดสอบบนฐาน PostgreSQL จำลองในสภาพแวดล้อมพัฒนา ไม่ได้เชื่อม Supabase ของผู้ใช้
ยังไม่มีการตรวจภาพบน browser Windows ของผู้ใช้
ดูรายงานงานที่ยังเหลือใน system-readiness-th.md ก่อนพิจารณาเปิด production
