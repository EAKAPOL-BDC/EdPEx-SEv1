# NEXORA: ปรับพื้นที่ทำงานและ F06 ให้ใช้งานเป็นลำดับ

โครงสร้างอ้างอิงจากภาพ LD Screen Primary ที่ผู้ใช้ส่งมา: แถบเมนูประจำด้านซ้าย,
ภาพรวมงาน, การ์ดสถานะ, หน้าลงชื่อเข้าใช้สองคอลัมน์ และลำดับงานที่ชัดเจน
คงโลโก้ มาสคอต ชื่อ NEXORA สีม่วง #583571 / #3d2451 และทอง #9b793b เดิม
ไม่ได้คัดลอกข้อมูลนักเรียน เมนูงานโรงเรียน หรือตัวเลขตัวอย่างมาใช้กับ EdPEx

## หน้าที่เปลี่ยน

- หน้าหลักและเข้าสู่ระบบ: ลำดับเนื้อหา/ปุ่มหลักชัดเจน ใช้โลโก้และมาสคอตเดิม
- ทุกหน้าที่ลงชื่อเข้าใช้: เมนูประจำ แสดงเมนูขอบเขตตาม persisted permissions
- ภาพรวม: งานของตนเอง รอบ F06 ที่มีสิทธิ์ และขอบเขตงานจริง ไม่แสดงคะแนนหรือข้อมูลผู้ตอบอื่น
- รอบ F06: การ์ดสถานะ ช่วงเวลา และเส้นทาง มอบหมาย → เก็บคำตอบ → คำนวณและตรวจผล
- มอบหมาย: แยกผู้ตอบ/หน้าที่ ระดับคาดหวังตามหมวด และด้าน M/T; ไม่กำหนดระดับล่วงหน้า
- กรอก F06: 6 หมวดตามคำถามที่ได้รับ ปุ่มก่อนหน้า/ถัดไป ความคืบหน้าการเลือกคำตอบ
  และแถบบันทึก; ค่าที่กรอกยังอยู่ใน form เดียว หมวดที่ซ่อนยังส่งไปกับ POST
- ช่องเหตุผล/ตัวอย่าง/แผนพัฒนา: ยุบเก็บและเปิดเมื่อมีข้อมูล ข้อผิดพลาด หรือเลือก N/A
- ตรวจผล: การ์ดผลรวมพร้อมค้นหา โดยใช้ packet ที่ผ่านสิทธิ์/กติกาซ่อนกลุ่มเล็กเดิม
- หน้าจอเล็ก: เมนูย่อ การ์ดเรียงใหม่ ตารางเลื่อนภายใน และแบบประเมินคอลัมน์เดียว

ไม่มี migration, การเปลี่ยนสูตร, การเพิ่มสิทธิ์อัตโนมัติ หรือการเปลี่ยนสถานะข้อมูลจาก GET
ฟอร์มปกติยังใช้ได้เมื่อปิด JavaScript โดยจะแสดงคำถามทุกหมวดต่อกัน
การสลับภาษาเก็บค่าฟอร์มในหน่วยความจำตามกลไกเดิม ไม่มี localStorage ของคำตอบ

## การตรวจที่ทำแล้ว

- `tests.test_web_portal`, `tests.test_operator_web`, `tests.test_self_assessments`: 56 tests ผ่าน
  รันผ่าน Django TestCase บนฐาน PostgreSQL แบบฝังตัว PGlite 18.3 ที่สร้างใหม่ในเครื่องทดสอบ
  ไม่มีการเชื่อมต่อ Supabase การทดสอบนี้ไม่ใช่การรับรอง PostgreSQL native 17 บน Windows
- Workflow ด้วยข้อมูลจำลอง 12 คน: มอบหมายผ่าน CSRF → ส่งคำตอบ → preview/commit →
  ส่งตรวจ → ผู้ตรวจอิสระรับรอง; 38 ชุดผล ตัวตั้ง/ตัวหารตรงตามที่คาด และย้อนข้อมูล QA ออกครบ
- `node --test tests/portal_language.test.js`: ผ่าน
- DOM interaction check ด้วย jsdom: 6 หมวด, navigation/keyboard focus, ค่าที่กรอกไม่หาย,
  ข้อความ N/A เปิดเหตุผล, หมวดข้อผิดพลาดแสดง, hidden sections อยู่ใน FormData,
  เมนูมือถือปิดด้วย Escape; ผ่าน
- โหลด template ทุกไฟล์และตรวจ Python/JavaScript syntax ผ่าน

ข้อจำกัด: เบราว์เซอร์ cloud ปฏิเสธการเปิด HTML ภายในเครื่อง จึงยังไม่ได้ตรวจภาพหน้าจอ
หรือยืนยัน visual layout บน Chrome/Windows จริง ต้องตรวจในฐานทดลองก่อนนำขึ้นใช้งานจริง

## เปิดดูบนเครื่อง Windows

แตกไฟล์ `nexora-ui-update.zip` ก่อน แล้วใช้ตัวเปิด `nexora_f06_demo_ui.py` ที่อยู่ข้าง `nexora-ui.bundle`
ตัวเปิดตรวจ SHA256 ของ bundle และ commit ที่กำหนด แล้วนำเข้าโค้ดจากไฟล์ในเครื่อง
และสร้าง git worktree แยกใต้ `C:\Users\User\EdPEx-Previews` เพื่อเก็บ UI รุ่นทดลอง
working tree เดิมและฐาน Supabase ไม่ถูกแก้ไข

ถ้าใช้ฐานทดลองเดิม ให้หยุดหน้าต่าง demo ด้วย Ctrl+C ก่อน แล้วเปิดตัว UI ด้วย `--resume`
และพาธ RUN เดิม รหัสผ่าน บัญชี และข้อมูลการฝึกยังใช้ชุดเดิม
ตัวเปิดจะสำรองไฟล์สถานะ/ตัวเปิดเก่าในโฟลเดอร์ RUN ก่อนอัปเดตพาธโค้ด
ไม่ต้องรัน migrate, seed หรือสร้างบัญชีใหม่

เส้นทางตรวจหน้าจอ: demo.manager → ภาพรวม → งานเก็บข้อมูล F06 → รอบ A → มอบหมาย;
จากนั้น demo.staff01 → แบบประเมินของฉัน → ทดลองเปลี่ยนหมวด/บันทึก;
demo.analyst → รอบ B → คำนวณ; demo.reviewer → ตรวจผลที่ส่งตรวจแล้ว

การเปลี่ยนนี้แยกจาก branch ของ staff workspace ที่เป็นฐาน และยังไม่ deploy/merge อัตโนมัติ
การส่งเข้า GitHub สาธารณะถูก automatic approval review ปฏิเสธ จึงจัดส่งเป็น bundle สำหรับเครื่องผู้ใช้แทน
