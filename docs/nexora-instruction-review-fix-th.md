# NEXORA — รับรองคำชี้แจงหลังตรวจภาษาแล้ว

ต่อจากชุดแก้การกลับหน้ารุ่น 522d909df1 สำหรับกรณีตรวจภาษาไทย–อังกฤษครบแล้ว แต่หน้าเผยแพร่ยังแสดง **คำชี้แจง: ยังไม่ตรวจ**

## สิ่งที่แก้

- การยืนยันความเหมาะสมของคำชี้แจงแยกจากการแก้เนื้อหา หากข้อความและข้อมูลเนื้อหาเดิมไม่เปลี่ยน ผลตรวจภาษา ผู้ตรวจ วันเวลาและรุ่นการตรวจจะคงเดิม
- เพิ่มปุ่ม **ตรวจและรับรองคำชี้แจง** ในหน้าเผยแพร่เมื่อยังขาดขั้นตอนนี้ และบอกเหตุผลให้ตรงจุด
- ไม่มีการติ๊กรับรองคำชี้แจงหรืออนุมัติคำแปลให้ผู้ใช้โดยอัตโนมัติ หากแก้ข้อความหรือข้อมูลเนื้อหา จะยังต้องตรวจคำแปลใหม่ตามกฎเดิม
- รูปแบบที่เผยแพร่แล้วคงแก้ไขไม่ได้ ต้องสร้างรุ่นใหม่ตามเดิม

## ติดตั้ง

1. แตก ZIP ทั้งชุดไปที่ `Downloads\nexora-instruction-review-fix`
2. หยุดเว็บด้วย Ctrl+C แล้วใช้ PowerShell หน้าต่างเดิมเรียก:

```powershell
& "$env:USERPROFILE\EdPEx-Web\EdPEx-SEv1\.venv\Scripts\python.exe" "$env:USERPROFILE\Downloads\nexora-instruction-review-fix\nexora_web_update.py" --apply-schema
```

คำสั่งนี้เพิ่ม migration `catalog.0004_instruction_curation_metadata` เพื่อแก้เงื่อนไขของฟังก์ชันตรวจระดับฐานข้อมูล ไม่มีการแก้คำถาม คำแปล สถานะรับรองเดิม ผู้ใช้ หรือคำตอบที่บันทึกไว้ อ่านแผนใน SCHEMA-UPDATE.md ประกอบ ตัวเปิดไม่ใช้ migration นอกแผนที่อนุญาต

เมื่อเว็บเปิด ใช้บัญชี edpexadmin และรหัสผ่านเว็บเดิม ครั้งต่อไปเรียกคำสั่งเดิมได้โดยไม่ต้องเติม `--apply-schema`

## รับรองคำชี้แจง F03

1. เข้า **คลังแบบฟอร์ม → F03 → 1. ชื่อและคำชี้แจง** หรือใช้ปุ่ม **ตรวจและรับรองคำชี้แจง** ในหน้าเผยแพร่
2. อ่านชื่อและคำชี้แจงทั้งหมด หากเหมาะสมกับการใช้งาน ติ๊ก **ตรวจความเหมาะสมของคำชี้แจงสำหรับผู้ตอบแล้ว** แล้วกด **บันทึกและดำเนินการ**
3. หากคงข้อความเดิม ผลตรวจภาษาเดิมจะคงอยู่ กลับไป **4. เผยแพร่** ควรเห็น **คำชี้แจง: ตรวจแล้ว**, **ค้างตรวจ: 0** และจำนวนตรวจครบ
4. เลือกชุดคำแปลที่ตรวจครบ ติ๊กยืนยันเผยแพร่ แล้วกด **บันทึกและดำเนินการ**
5. กลับไป **แบบสำรวจ F01–F04 → สร้างรอบแบบสำรวจ** แล้วเลือก F03 ที่เผยแพร่แล้ว

หากอ่านแล้วต้องปรับข้อความ ให้แก้ตามความเหมาะสม จากนั้น **เตรียมคำแปลไทย–อังกฤษ** และตรวจข้อความที่ระบบให้ตรวจใหม่ก่อนเผยแพร่ ชุดแก้ไขนี้ไม่คืนสถานะให้รายการที่ถูกเปลี่ยนเป็นรอตรวจก่อนติดตั้ง เพราะไม่สามารถถือว่าเนื้อหานั้นยังผ่านการตรวจอยู่ได้

## ผลตรวจ

ผ่านการทดสอบ 12 กรณีในฐานแยกด้วยข้อมูลสมมติ: ยืนยันคำชี้แจง F03 แล้วเผยแพร่โดยคงผลตรวจเดิม, เปลี่ยนข้อความแล้วยังบังคับตรวจใหม่ทั้งผ่านเว็บและ SQL, ไม่อนุมัติคำแปลที่รอตรวจ, คงแถวและประวัติเดิมขณะเปลี่ยนฟังก์ชัน migration, ต้องรับรองคำชี้แจงก่อนเผยแพร่, ห้ามแก้รุ่นเผยแพร่, สิทธิ์ผู้ใช้, แผน migration, snapshot การตรวจที่ล้าสมัย และงาน F06 จนส่งคำตอบ

ใช้ Django 5.2.17 และ PGlite ผ่าน migration จริงของโครงการ ตรวจ system check และตัวติดตั้งแบบ install-only แล้ว ยังไม่ได้ติดตั้งบนเครื่อง Windows หรือเชื่อมฐาน Supabase ของผู้ใช้
