# NEXORA — การจัดวางส่วนร่วมของระบบ

รุ่นปรับปรุงวันที่ 17 กันยายน 2569

## สิ่งที่เปลี่ยนตามภาพที่แจ้ง

| ส่วน | การปรับปรุง | การใช้งาน |
|---|---|---|
| โลโก้และชื่อหน่วยงาน | ใช้โลโก้เดิม จัดชื่อวิทยาลัยและมหาวิทยาลัยสองบรรทัดข้างโลโก้ มีเส้นแบ่งและระยะห่างที่สัมพันธ์กัน | กดโลโก้กลับหน้าหลัก ขนาดปรับตามหน้าจอ |
| แถบเมนู | เพิ่มความกว้างและขนาดตัวอักษร จัดหมวดเก็บข้อมูล แบบฟอร์ม วิเคราะห์ จัดการ และบัญชี/คู่มือ มีไอคอนและสถานะหน้าปัจจุบัน | กดชื่อหมวดเพื่อยุบหรือขยาย บนจอเล็กเปิดจากปุ่มเมนูพื้นที่ทำงาน |
| หัวข้อและพื้นที่ข้อมูล | ใช้สัดส่วนหัวข้อร่วมกัน จัดปุ่มงานใกล้ชื่อหน้า รวมจำนวน กราฟสถานะ ตัวกรอง และคำอธิบายจำนวนไว้ในพื้นที่เดียว | ค้นหาและกรองตามเดิม กราฟแสดงสถานะรอบตามสิทธิ์และตัวกรอง ไม่ใช่คะแนนประเมิน |
| ผู้พัฒนาและลิขสิทธิ์ | ตรึงส่วนท้ายในแถวแยกจากเนื้อหา เพิ่มขนาดข้อความและไอคอน จัดซ้าย–ขวาบนจอกว้างและเรียงบรรทัดบนจอเล็ก | อ่านข้อมูลผู้พัฒนาและลิขสิทธิ์ได้ตลอดการเลื่อนพื้นที่ทำงาน |
| ส่วนที่เกี่ยวข้อง | ใช้โลโก้และส่วนท้ายร่วมกันในพื้นที่ทำงาน หน้าสาธารณะ แบบสำรวจ และ Django Admin พร้อมแก้การสลับภาษาในหน้าคู่มือ | การสลับภาษาเก็บค่าที่กำลังกรอกและตำแหน่งเลื่อนพื้นที่ทำงานไว้ |

รูปแบบหัวข้อครอบคลุมหน้ารายการ คลังแบบฟอร์ม Dashboard คู่มือ และ Data Visualization ที่ใช้ส่วนร่วมของระบบ พื้นที่สรุป/ค้นหาปรับโดยตรงในหน้าเตรียมรอบ แบบสำรวจ F01–F04 กิจกรรม F05 งาน F06 และคลังแบบฟอร์ม

## การเลื่อนและเมนู

บนคอมพิวเตอร์ ส่วนหัวและส่วนท้ายอยู่กับที่ เมนูด้านข้างและพื้นที่เนื้อหาเลื่อนแยกกัน กลุ่มเมนูเปิดไว้ตั้งต้น ผู้ใช้ยุบหมวดที่ไม่ต้องการได้ และหมวดที่มีหน้าปัจจุบันจะเปิดให้อัตโนมัติ เมนูยังแสดงตามสิทธิ์เดิมของบัญชีและพื้นที่ทำงาน

เมื่อความกว้างหน้าต่างไม่เกิน 1,023 พิกเซล เมนูเปลี่ยนเป็นแผงเปิด–ปิด กดปุ่มปิด พื้นหลัง หรือ Escape เพื่อปิดได้ ขณะเปิด Tab จะวนในแผงเมนู และเมื่อปิดจะกลับไปยังปุ่มเปิดเมนู หาก JavaScript ไม่ทำงาน เมนูยังแสดงเป็นรายการในพื้นที่เลื่อนตามปกติ

ใน Django Admin ยังคงวิธีเลื่อนเอกสารเดิมเพื่อรองรับปฏิทินและเครื่องมือมาตรฐาน ส่วนท้ายวัดความสูงจริงและกันพื้นที่ด้านล่างให้เนื้อหา หากเบราว์เซอร์ไม่มี ResizeObserver ส่วนท้ายจะแสดงตามลำดับเอกสาร การพิมพ์ซ่อนส่วนท้ายและคลายพื้นที่เลื่อนเพื่อให้เนื้อหาออกครบ

## ตรวจรับหลังติดตั้ง

1. เปิดระบบและกด Ctrl+F5 ตรวจโลโก้ ชื่อหน่วยงาน และผู้พัฒนาว่าไม่มีข้อความทับกัน
2. เปิดหน้าเตรียมรอบ แบบสำรวจ F01–F04 กิจกรรม F05 งาน F06 และคลังแบบฟอร์ม ตรวจหัวข้อ ปุ่ม จำนวน และตัวกรอง
3. เลื่อนเนื้อหาจนสุด ตรวจว่าปุ่มกลับหน้าหลักและข้อมูลแถวสุดท้ายเข้าถึงได้ โดยส่วนท้ายไม่บังเนื้อหา
4. ยุบและขยายหมวดเมนู แล้วเปิดหน้าที่ต้องการ ตรวจสถานะเมนูหน้าปัจจุบัน
5. ย่อหน้าต่าง ลองเปิดเมนู ใช้ Tab/Shift+Tab และ Escape และตรวจว่าพื้นที่เนื้อหากลับมาใช้งานได้
6. ในรอบทดสอบ กรอกค่าฉบับร่างโดยยังไม่ส่ง สลับไทย/EN ตรวจว่าค่าที่กรอกยังอยู่และการเตือนก่อนออกจากหน้ายังทำงาน
7. เปิดคู่มือ สลับภาษา และตรวจว่าข้อมูลผู้พัฒนาไม่ถูกนำไปแทนส่วนท้ายของเอกสารคู่มือ
8. เปิด /admin/ และหน้ารายการผู้ใช้ ตรวจโลโก้ ส่วนท้าย และปุ่มงาน รวมถึงการเปลี่ยนธีมและย่อหน้าต่าง
9. ตรวจเพิ่มบน Chrome/Windows ที่ใช้งานจริง หน้าจอแคบ และการขยายตัวอักษร 200% โดยเฉพาะข้อความยาวและส่วนท้ายหลายบรรทัด

## ผลตรวจและข้อจำกัด

- ผ่าน Django 13 กรณี ครอบคลุมโครงหน้า 12 ส่วน สิทธิ์ เมนู หน้าเข้าใช้ระบบ แบบสำรวจ คู่มือ Admin และการบันทึกคำตอบเดิม
- ผ่าน JavaScript 9 กรณี ครอบคลุมเมนูมือถือ คีย์บอร์ด การเปลี่ยนขนาดหน้าต่าง การสลับภาษา ค่าแบบฟอร์มที่ยังไม่บันทึก และการกันพื้นที่ส่วนท้าย Admin
- ตรวจคอมไพล์เทมเพลต 78 ไฟล์และตรวจไวยากรณ์ CSS แล้ว
- ชุดทดสอบใช้ฐานข้อมูลแยก ไม่มีการเชื่อมต่อหรือแก้ข้อมูลจริงของผู้ใช้
- ยังไม่ยืนยันภาพจริงหรือพฤติกรรมการจัดวางผ่านเบราว์เซอร์: เครื่องมือตรวจเว็บไม่สามารถเปิด localhost ได้ (ERR_BLOCKED_BY_CLIENT) ผลทดสอบ DOM ไม่ใช่ผลตรวจภาพหรือการรับรอง WCAG
- ไม่มี migration ใหม่ การปรับครั้งนี้ไม่เปลี่ยนสูตรคำนวณหรือให้สิทธิ์เพิ่มเติม

## สำหรับผู้พัฒนา

- `brand_identity.html` และ `footer_content.html` เป็นส่วนร่วมของแบรนด์และข้อมูลผู้พัฒนา
- `identity.css` กำหนดสัดส่วนแบรนด์และส่วนท้าย; `shell.css` กำหนดโครงหน้าและองค์ประกอบร่วม โดยโหลดหลัง CSS เดิม
- `navigation.html` ใช้เงื่อนไขสิทธิ์เดิม; `navigation.js` ดูแลแผงเมนูและโฟกัส
- `admin-frame.js` วัดความสูงส่วนท้ายของ native Admin โดยไม่เปลี่ยนกลไกเลื่อนหลัก
- `language.js` เปลี่ยนเฉพาะ header/main/footer ลูกโดยตรงของ body เพื่อไม่ชน footer ภายในเอกสาร
- เมื่อเพิ่มหน้าใหม่ ให้ใช้ `portal/base.html` และส่วน heading/collection ที่มีอยู่ ตรวจกรณีชื่อยาว ไม่มีข้อมูล สิทธิ์จำกัด และจอแคบทุกครั้ง
