# NEXORA: เมนูหน้าหลักและการนำทางตามบริบท

รุ่นปรับปรุง 17 กันยายน 2569 · คู่มือ 1.2

## สิ่งที่เปลี่ยน

- เปลี่ยนชื่อหัวเมนูและลิงก์ภาพรวมเป็น **หน้าหลัก / Home** และชื่อเมนูมือถือเป็นเมนูหลัก
- ใช้ Breadcrumb ส่วนกลางในหน้ารายการ หน้ารายละเอียด หน้ากรอกข้อมูล หน้าคู่มือ บัญชี และแบบสำรวจ แสดงหน้าปัจจุบันด้วย `aria-current="page"` ไม่มีลิงก์ย้อนมาที่หน้าเดิม
- เพิ่มแถบท้ายหน้า กลับรายการ/รอบต้นทาง และกลับหน้าหลัก แสดงทางไปต่อเฉพาะเมื่อมีสิทธิ์และสถานะรอบพร้อม
- คู่มือมีสารบัญย่อ/ขยายได้ ลิงก์บทก่อนหน้า บทถัดไป และกลับสารบัญ ภาพเปิดขนาดเต็มได้ คงดาวน์โหลด PDF ครบ 26 เล่ม
- ลดขนาดหัวหน้า ระยะห่าง ไอคอน และการ์ดคู่มือให้อยู่ในชุดรูปแบบเดียวกัน คงตัวอักษรเนื้อหาคู่มือที่อ่านได้สบาย
- ปรับหัวหน้าและ Breadcrumb ใน Django admin ให้มีสัดส่วนสอดคล้องกับระบบหลัก โดยคงเครื่องมือจัดการเดิม

## จุดที่แก้เพิ่มเติม

- หน้าตรวจผล F05 เคยใช้ Breadcrumb หมวดแบบสำรวจ แก้ให้กลับรอบ F05 และแสดงเมนู F05 เป็นเมนูปัจจุบัน
- ปุ่มยกเลิกเพิ่มช่วงรายงานเคยกลับหน้ารวม แก้ให้กลับต้นทางที่ถูกต้องจากค่าต้นทางที่อนุญาต
- ลิงก์จัดการรอบ F05 แสดงเฉพาะผู้มีสิทธิ์จัดการรอบ ปุ่มเพิ่มกิจกรรมและคำนวณแสดงตามสถานะงานที่บริการรองรับ
- ไม่แสดงแถบนำทางเดิมซ้ำกับส่วนกลาง
- อัปเดตภาพเมนูและคำอธิบายการนำทางในคู่มือ/PDF ให้ตรงกับหน้าระบบ

## การบำรุงรักษาสำหรับนักพัฒนา

- `apps/accounts/wayfinding.py` สร้าง Breadcrumb, parent และ next จาก context ที่ view ตรวจสอบแล้ว ตรวจสิทธิ์ด้วย `can_access` เดิม
- `portal_ui.page_navigation` เรียกจาก base template; `cancel_destination` ใช้ปลายทางเดียวกัน
- `portal/components/breadcrumbs.html` และ `page_navigation.html` เป็นส่วนประกอบร่วม โหลด CSS `portal/wayfinding.css` หลัง shell
- งานหลายขั้นตอนที่ต้องเปลี่ยนข้อมูลยังใช้ POST, CSRF, การตรวจ revision และบริการเดิม ลิงก์ทางไปต่อมีไว้เปิดหน้าเท่านั้น
- `apps/manuals/views.py` เพิ่มลิงก์บทในสำเนาข้อมูลสำหรับเว็บ ไม่แก้ canonical content ที่ใช้ตรวจ checksum ของ PDF
- เมื่อเพิ่มหน้าใหม่ให้กำหนดหมวดและต้นทางใน wayfinding พร้อมตรวจสิทธิ์ อย่าอ่าน scope หรือ record เพิ่มจาก Referer
- ไม่เพิ่ม migration ในรุ่นนี้ และไม่สร้าง/แก้คำตอบจริงจากการนำทาง

## ผลตรวจและข้อจำกัด

ผ่านการทดสอบฝั่งระบบ 59 กรณี (wayfinding + shell + reporting period + manuals รวม 27; F06 operator + F05 stored workflow รวม 32) และการโต้ตอบ JavaScript 8 กรณี ตรวจโครงสร้าง HTML, การนำทางตามสิทธิ์/สถานะ, การกรอกผิดและยกเลิก, ลิงก์ทุกบทของคู่มือ, การรักษาแหล่งข้อมูล PDF, เมนูมือถือ และคำเตือนข้อมูลยังไม่บันทึก

PDF 26 เล่ม รวม 290 หน้า: ตรวจการเรนเดอร์ ขอบเขตเนื้อหา และหน้าที่แก้ไข ไม่พบข้อความออกนอกหน้า/หน้าว่างจากการตรวจอัตโนมัติ
