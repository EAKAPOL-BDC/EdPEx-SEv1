# เว็บและสิทธิ์องค์กร ระยะที่ 1

เพิ่มหน้าแรก `/`, เข้าสู่ระบบ `/login/`, พื้นที่ทำงาน `/workspace/` และจัดการสมาชิก/บทบาทตามขอบเขต
ยังใช้ Django auth.User เดิม และ `/admin/` เดิม ไม่มี migration ใหม่
ระยะนี้สำหรับทดสอบในเครื่อง ยังไม่ใช่ชุดเปิดเว็บสาธารณะ: ต้องเพิ่มการป้องกันการลองรหัสผ่านซ้ำและการตั้งค่า production ก่อน deploy
แบบฟอร์ม/แดชบอร์ด EdPEx และการสร้างขอบเขตย่อยผ่าน UI เป็นงานถัดไป

## 1. รับโค้ดที่ผ่านการตรวจ

รอ PR ผ่าน CI และตรวจโค้ดก่อน merge จากนั้นใน PowerShell ที่เปิดเว็บอยู่กด Ctrl+C
ตรวจ `git status --short` หากมีรายการแก้ไขในเครื่อง ให้จัดการเก็บงานก่อน ไม่ใช้ reset ทิ้งงาน
เมื่ออยู่บน main และไม่มีงานค้าง:

```powershell
git pull --ff-only origin main
& $WebPython -m pip install -r requirements.txt
& $WebPython manage.py check
```

ใช้หน้าต่างเดิมที่ตั้งค่า Supabase development ไว้ถูกต้องแล้ว ไม่ต้องรัน migrate หรือ createsuperuser ซ้ำ
อย่ารัน `manage.py test` กับ Supabase; CI ใช้ PostgreSQL ชั่วคราวแยกต่างหาก

## 2. ระบุองค์กรและผู้ดูแลครั้งแรก

คำสั่งนี้เป็นงานของผู้ดูแลระบบที่ได้รับมอบหมาย เป็นการให้สิทธิ์องค์กรอย่างชัดเจน ไม่ใช่ให้สิทธิ์อัตโนมัติจาก is_superuser
UUID ต่อไปนี้กำหนดไว้สำหรับองค์กรวิทยาลัยการศึกษาในโครงการนี้ ให้ใช้ค่าเดิมเมื่อรันซ้ำ
ตรวจชื่อบัญชีจากหน้า Django admin และแก้ `edpexadmin` ในบล็อกหากชื่อจริงต่างกัน (ตัวพิมพ์เล็กใหญ่ต้องตรง)

```powershell
$OrgId = 'e1eddf63-328e-4b31-b4c8-c6c09f26af84'
$OrgName = 'วิทยาลัยการศึกษา มหาวิทยาลัยพะเยา'
$OrgAdmin = 'edpexadmin'
$OrgReason = 'ตั้งผู้ดูแลองค์กรครั้งแรกตามการมอบหมายของวิทยาลัยการศึกษา'
& $WebPython manage.py bootstrap_organization --organization-id $OrgId --name $OrgName --username $OrgAdmin --reason $OrgReason
```

ต้องเห็น `PREVIEW ONLY. No data written.` ตรวจองค์กร บัญชีผู้ดูแล และรายการสิทธิ์ให้ครบก่อนขั้นถัดไป
ผู้ดูแลเริ่มต้นได้รับรายการสิทธิ์ M1 ทั้งหมดและครอบคลุมขอบเขตย่อยที่อาจสร้างในอนาคต
สิทธิ์ self.read/self.write ยังจำกัดตัวเจ้าของ ไม่มีสิทธิ์อ่านคำตอบดิบหรือให้คะแนน F06 แทนผู้อื่นเพิ่มขึ้น

## 3. บันทึกองค์กรและสิทธิ์ครั้งแรก

เมื่อแผนถูกต้อง ให้รันบรรทัดนี้ครั้งเดียว:

```powershell
& $WebPython manage.py bootstrap_organization --organization-id $OrgId --name $OrgName --username $OrgAdmin --reason $OrgReason --apply
```

ต้องเห็น `Organization initialized.` คำสั่งบันทึกองค์กร ขอบเขต สมาชิก บทบาทเริ่มต้น และ audit ภายใน transaction เดียว
รันซ้ำด้วยค่าเดิมจะไม่สร้างซ้ำ หากองค์กรมีอยู่แล้วแต่ไม่ใช่การตั้งครั้งแรกนี้จะหยุด
หากสิทธิ์แรกถูกเพิกถอนแล้วจะไม่คืนสิทธิ์ให้อัตโนมัติ
หากพบชื่อองค์กรซ้ำ ห้ามเปลี่ยน UUID เพื่อฝืนสร้างองค์กรใหม่

## 4. เปิดเว็บ

```powershell
& $WebPython manage.py runserver 127.0.0.1:8000
```

เปิด http://127.0.0.1:8000/ กดเข้าสู่ระบบ ใช้บัญชีเดิม
เปิดพื้นที่ทำงาน เลือก “จัดการสมาชิกและบทบาท” ของวิทยาลัย
ถ้ายังไม่มีสิทธิ์จะเห็นข้อความให้ติดต่อผู้ดูแล ไม่แสดงองค์กรอื่น

## 5. เพิ่มบุคลากรทีละคน

1. ผู้ดูแลบัญชีเข้า `/admin/` → ผู้ใช้ → เพิ่มบัญชีจริง ตั้งรหัสผ่านเริ่มต้นเป็นส่วนตัว
2. ผู้ใช้งานทั่วไปไม่ต้องเปิดสถานะ staff หรือ superuser เพื่อใช้งานหน้าเว็บ
3. ผู้ดูแลองค์กรเข้า `/workspace/` → จัดการสมาชิกและบทบาท
4. ช่องเพิ่มสมาชิก: กรอกชื่อผู้ใช้ตรงตามบัญชี แล้วกดเพิ่มสมาชิก
5. ช่องมอบบทบาท: เลือกสมาชิกและบทบาท ดูตารางด้านล่าง กำหนดวันสิ้นสุดตามหน้าที่ แล้วกดมอบบทบาท
6. ถ้าผู้มอบมีสิทธิ์จำกัดเวลา ต้องกำหนดวันสิ้นสุดไม่เกินของผู้มอบ การปล่อยว่างหมายถึงไม่สิ้นสุดและจะถูกปฏิเสธ
7. เลือกรวมขอบเขตย่อยเฉพาะเมื่อได้รับมอบหมายจริง

| บทบาท | สิทธิ์ |
|---|---|
| organization-manager-v1 | จัดการสิทธิ์และงาน M1 ในขอบเขตที่มอบ ใช้กับผู้ดูแลองค์กรที่ได้รับมอบหมาย |
| catalog-reader-v1 | อ่าน catalog ในขอบเขต (หน้ารายการ catalog จะพัฒนาถัดไป) |
| self-service-v1 | อ่าน/แก้ข้อมูลตนเองตามบริการที่รองรับ (หน้าแบบฟอร์มจะพัฒนาถัดไป) |

การเป็นสมาชิกอย่างเดียวยังไม่ให้สิทธิ์ทำงาน ใช้การมอบบทบาทแยกต่างหาก
การมอบบทบาทไม่แก้ is_staff/is_superuser ไม่ส่งอีเมล และไม่เพิ่มผู้ใช้ใน Supabase Auth
สมาชิกที่ถูกระงับจะไม่ถูกเปิดกลับด้วยปุ่มเพิ่มสมาชิก

## 6. ทดสอบสิทธิ์ก่อนใช้จริง

- เข้าด้วยผู้ดูแลองค์กร: เห็นหน้าจัดการสมาชิก
- ใช้หน้าต่างไม่ระบุตัวตน เข้าด้วยสมาชิกธรรมดา: เห็นเฉพาะขอบเขตที่ได้รับสิทธิ์
- สมาชิกธรรมดาเปิด URL จัดการสมาชิกโดยตรง: ต้องถูกปฏิเสธ ไม่มีสิทธิ์เพิ่มจากการรู้ URL
- ผู้ดูแลกดเพิกถอนบทบาททดสอบ แล้วสมาชิกรีเฟรช: ขอบเขตที่ไม่เหลือสิทธิ์ต้องหายไป
- ออกจากระบบแล้วเปิด `/workspace/`: ต้องกลับไปหน้าเข้าสู่ระบบ
- อย่าเพิกถอนผู้ดูแลองค์กรคนสุดท้ายถ้ายังไม่ได้มอบหมายคนใหม่

## 7. ขั้นถัดไป

เมื่อระยะนี้ผ่าน จึงเพิ่มหลังบ้านฉบับร่าง/รุ่นแบบฟอร์มผ่าน catalog services เดิม ตาม Blueprint 1.2 / Instruments 1.1
จากนั้นเตรียม production settings, HTTPS, static files, login rate limiting, secret management, monitoring และสำรองข้อมูลปัจจุบัน
สำเนา empty-public ก่อนติดตั้งเดิมไม่มีบัญชีและองค์กรที่เพิ่งสร้าง จึงไม่ใช่สำเนาสำหรับย้อนกลับข้อมูลผู้ใช้ปัจจุบัน
